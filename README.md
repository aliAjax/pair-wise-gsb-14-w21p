# 油品价格维护

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

油站换班场景下，两个窗口可能同时提交未来价格，页面重开后还要补上停用期间错过的切换。
本项目把**调价单、价格时间轴、操作台账**三者连起来，数据保存在浏览器 localStorage（schema v2）。

## 业务规则

1. **同一油品同一时刻只留一个有效价**：价格时间轴是按油品的阶梯函数，批准新价时若该时刻已有未撤销生效点，判为撞点。
2. **时间轴一变旧草稿失效**：每成功落下一个生效点，时间轴版本 +1；基于旧版本的待批准调价单自动置为"已失效"，需重排后再提交。
3. **晚到窗口保留草稿并提示重排**：撞点不丢弃调价单，标记"撞点·待重排"，改一个生效时刻即可重新挂起。
4. **批量提交可重试、重开续办、不重复记账**：批次先暂存（stage）再逐条提交；每条带稳定幂等键（批次 id + 序号），
   中途失败只留未完成条目，重试同一批次只补未完成部分，页面重开自动续办；时间轴生效点与台账记录均按幂等键去重。
5. **旧数据迁移成时间轴最初版本**：首次进入或检测到旧版数据时，分批迁移（每拍一条、即时落库），
   中断后刷新页面从 cursor 继续完成；同油品同日期的旧价并入同一生效点不重复建价；旧价在"旧价查询"中永久只读可查。
6. **重开补切换**：心跳记录最后在线时间，重开时把停用期间到期的生效点补执行，并写入"补切换"台账。
7. **回滚只撤指定版本**：把该版本生效点标记为已撤销（revoked），其后批准的价格版本、生效时刻完全不受影响。

## 数据模型（src/types.ts）

- `PricePoint`：价格时间轴生效点（版本号、生效时刻、active/scheduled/expired/revoked、幂等键、来源 migration/draft/batch）
- `PriceOrder`：调价单草稿（所依据的 baseVersion，submitted/applied/stale/conflict）
- `PriceBatch / BatchItem`：批量提交与条目（稳定 idemKey、attempts、状态）
- `LedgerEntry`：操作台账（全局递增 seq + 业务幂等键，重放不产生重复条目）
- `LegacyRecord / MigrationState`：旧价与可续跑的迁移游标

## 页面

今日有效价 / 调价单 / 批量提交 / 价格时间轴（含版本回滚）/ 操作台账（分类与油品筛选）/ 迁移（中断/续跑演示）/ 旧价查询。
"迁移"页内置一键演示：迁移中断后续跑、重开补切换、批量失败→重试续办；多开浏览器标签页可模拟换班两个窗口同时提交。
